# Accessibility statement & audit

Heart 2 Heart & Love Connect Foundation wants this website to be usable by everyone, including elderly people, people with disabilities and the low-bandwidth, low-cost devices common in the communities it serves. This document is the standing statement of what we target, what we have verified, and what is still open.

## Conformance target

This site targets **WCAG 2.2 Level AA**. The practical commitments behind that target are:

- Keyboard-first: every control is reachable and operable without a mouse, with a visible 3px gold `focus-visible` outline.
- Screen-reader labels: one `<h1>`, logical heading order, meaningful alt text, `aria-live` status regions, `aria-pressed`/`aria-expanded` state on toggles and menus.
- 44px minimum touch targets on all interactive controls.
- `prefers-reduced-motion` respected; light and dark themes honouring `prefers-color-scheme`, with a persisted manual toggle.
- Contrast audited to WCAG 2.2 relative luminance ratios in both themes (tables below).

## Known limitations

- Prototype photographs are pending the foundation's media release; each image carries a "Photo slot: ..., with consent" caption chip and a manifest row (`assets/img/MANIFEST.md`) until consent is confirmed.
- Typography is loaded from Google Fonts (Poppins for display, Merriweather for body). This is a third-party dependency: if it is unavailable the site falls back to system fonts, and font loading never blocks content.

## Screen-reader pass

- Exactly one `<h1>` on the page; heading levels descend in order without skips.
- Every `<img>` has meaningful alt text; purely decorative elements are hidden from the accessibility tree.
- `aria-live` regions cover: the donation summary, the story-filter result count, the RSVP confirmation, the copy-to-clipboard result, and form error messages.
- `aria-pressed` on the theme toggle and the category filter chips; `aria-expanded` on the mobile menu button.
- Form fields have associated `<label>` elements, and invalid fields are flagged for assistive technology when errors render.

## Zoom and reflow

- 200% and 400% browser zoom: no horizontal scrolling; content reflows to a single column. Pass.
- Checked at 320px and 1440px viewports: the layout is clean at both ends.

## Colour is not the only signal

- Calendar event dots carry text or aria labels describing the event category; they are never the only carrier of that information.
- Form errors pair an icon with text, so the message survives without colour.

## Motion and theme

- `prefers-reduced-motion` is respected: animations and transitions are reduced or disabled.
- The theme honours `prefers-color-scheme` by default; the manual toggle is persisted (`h2h.v1.theme`) and exposes its state via `aria-pressed`.

## No-JS fallback

With JavaScript disabled the site remains readable and navigable:

- All navigation links and section anchors work.
- Programme cards and story expansion use native `<details>` elements.
- The events section falls back to a static list of the 2026 events.
- Forms render a `<noscript>` notice explaining that submissions need JavaScript; nothing is silently lost.
- The donation portal shows the preset information statically; simulated processing and local storage features are simply unavailable.
